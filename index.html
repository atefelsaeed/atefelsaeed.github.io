Co-founder · sole mobile developercom.dkonline.app

Dikirnis On

Context
A local super-app for Dikirnis, Egypt. One place for 10+ sectors: doctors and clinic bookings, jobs, a buy-and-sell market, stores and offers, home and car services, education, sports, restaurant ordering and local news. A second app, Dikirnis On Pro, lets businesses run their own store.
My role
Co-founder and the only mobile developer. I built both apps with Flutter, Bloc and go_router, integrated with a .NET REST API, and handle every store release.
Key decision
Most sectors are listings, so I built one data-driven listing UI instead of a screen per sector. Categories nest to any depth. When the team adds or reorders a sector in the dashboard, it appears in the app right away, with no new release. Features with their own logic (jobs, the market, bookings) are separate modules.
Result
2,500+ users and 500+ registered businesses within 5 months of the May 2026 launch.

Performance & re-architecturecom.almasdaralawal.hajj

Al-Masdar Al-Awal · Prime Source

Context
An operations app for organizing Hajj: pilgrim housing, transport and on-site coordination, plus Quran, Athkar and Duas. Five kinds of users share one app, each with their own job.
The problem
The app had grown to 250 MB. It carried many font files, duplicated images and assets, a lot of dead code, unused packages, and an architecture that made every change harder.
What we did
Re-structured the whole app, removed duplicate fonts and images, dead code and unused dependencies, then shipped a redesign with new features and performance improvements.
Result
From 250 MB to 85 MB, a 65% smaller download for pilgrims who often install it on mobile data.

Open source · in active developmentgithub.com/atefelsaeed/RepoSphere

RepoSphere

Context
A unified dashboard for developers who work across many repositories on more than one Git provider. Repos, commits, pull requests, issues, releases, notifications and gists from GitHub and GitLab in one place, instead of switching between tabs and accounts.
My role
Built solo and open source, from the product spec and design system to the code. Flutter, web-first, with the same codebase targeting Android, iOS, macOS, Windows and Linux.
Technical decisions
Clean Architecture with domain, data and presentation layers, Riverpod for state and GoRouter for navigation. Each provider has its own data source behind one repository, so GitLab was added without touching the screens. GitHub sign-in uses the OAuth Device Flow, tokens live in secure storage, and an expired token anywhere in the app logs the user out through one global observer.
Quality
GitHub Actions runs static analysis, tests and a web build on every push. Sentry for crash reporting. Work is planned in sprints and documented in the repository.
Next
Multi-account support, so one person can connect several GitHub and GitLab accounts, for example one per client.
